# 需求问询

需求确认前必须先问人。目标：用最少的来回，把所有会影响成片的决定一次问清，写成 `需求确认.md`。

## 问法

- 先完成预调研再问。问题和选项要**具体到这个产品**（「高潮镜头让 AI 一句话变出记账应用」而不是「高潮镜头展示什么」）。
- 用结构化提问工具（Cursor 的 `AskQuestion`、Claude Code 的 `AskUserQuestion`、pi 的 `questionnaire`；都没有就在回复里列编号选项），一轮 5~8 个问题，通常两轮问完。每题第一项是推荐项，标 `（推荐）`，选项文字里带一句理由（pi 的 `questionnaire` 把理由写在 `description` 里，标签栏用 `label` 写短标签）。
- 第一轮之前先跑过 `doctor.py`，知道用户有没有 ElevenLabs key、能不能截图，声音和截图两题的选项要按实际条件给。
- 用户回答「你来决定」时，自己拍板，但在 `需求确认.md` 里写明你的决定和理由，让用户在确认环节能看到。
- 用户补充了自由文本（例如「不考虑授权问题」「不需要我本人的声音」），原话记进 `需求确认.md`。

## 第零步：产品状态不明时先问定位

预调研发现产品**没有官方来源**（还没发布、只有灰度传闻、版本号对不上）时，在第一轮之前单独问这一题，因为它决定后面所有素材和事实怎么用：

| id | 问题 | 选项 |
|---|---|---|
| direction | 官方还没发布，片子怎么做？ | 先备好风格、配乐、框架，官方发布当天填官方数据（推荐）/ 改做已发布的版本 / 改做同系列已发布的模型 + 结尾悬念 / 现在做「抢先看」：只用网友实测，逐条标出处，全片标注「未经官方确认」/ 用户自己有可靠信息源 |

选了「抢先看」：画面常驻一个「网友实测 · 未经官方确认」标记；不出现任何官方跑分、价格、功能说法；结尾用官方新闻页的真实截图说明「官方还没确认」。距离开工超过半天再交付时，重新核实一次官方状态和新出现的案例。

## 第一轮：定方向

| id | 问题 | 常见选项（按产品改写） |
|---|---|---|
| deliverable | 交付物 | MP4 + 同源网页版（推荐）/ 只要 MP4 / 只要网页 |
| format | 画幅与时长 | 16:9 约 45~60 秒（推荐）/ 30 秒快剪 / 70~90 秒完整版（需说明理由）/ 9:16 竖屏优先 / 横竖双版 |
| hook | 开场钩子（3 秒内；必须让完全不了解背景的人听懂第一句） | 痛点切入：用目标用户最真实的 2~3 个痛点快速连击（推荐，写出这个产品的具体痛点）/ 核心亮点切入：第一秒就亮出最震撼的数字或作品 / 结果切入：先放最终成果再倒叙 |
| audience | 主受众 | 按产品列 2~4 类人群 + 平均覆盖 |
| style | 风格方向 | **3~4 个针对该产品的方向，附风格样帧**（见下） |
| story | 叙事结构 | 从 `风格方向.md` 的叙事菜单挑 2~3 个最合适的，写成这个产品的具体版本。每个选项都写出「旁白第一句」，让用户判断外行能不能听懂 |
| hero | 高潮镜头 | 最能体现产品价值的一个画面，列 2~3 个具体方案 |
| audio | 声音 | **有 ElevenLabs 账号**：按分镜作曲 + v4 旁白（推荐）/ 纯音乐卡点 + 大字 / 用户本人录音 / 结尾一句本人声音。先用 `elevenlabs.py quota` 和 `voices` 查账号套餐与音色。**没有账号**：曲库配乐卡点 + 大字（推荐）/ 用户本人录音 / 现在去注册 ElevenLabs、把 key 写进工作区根目录的 `.env`。**音色不在这一轮拍板**：写好旁白稿后，用 3 个候选（账号里有用户本人的克隆音色就算一个，其余从音色库挑）各念 3 句代表句，放进 `工程/out/音色候选/` 请用户试听再定（克隆音色在 Fable 一片里被评「音调怪」，转写也最容易错）。用户直接给了音色 ID 就用它，不再挑候选；但这个音色没为默认模型训练时，要在汇报里说明换了哪个模型 |

### 风格样帧（style 这一题必须做）

1. 从 `风格方向.md` 挑或自创 3~4 个**彼此差异明显**的方向，至少一个非常规的（Q 版 / 手绘 / 像素 / 黏土 / 国潮……）。不要四个都是「深色科技感」的变体。
2. 每个方向出一张 16:9 样帧：画面里放这个产品真实的名字、一句真实文案、一个代表性元素，让用户看到「用在我的产品上是什么样」。有生图工具（Cursor 的 `GenerateImage`、Codex 的图像生成等）就用它；pi 本身不带生图，装了生图 MCP / 扩展才用，否则按「没有生图工具」处理：用 HTML/CSS 画一张 1920×1080 的页面，用 `python3 <工具目录>/template/scripts/shot.py file:///<绝对路径>/A.html A --out "<输出目录>/<中文项目名>/样帧"` 截出来（代码画得出的风格：极简、排版、像素、霓虹、界面实录；需要角色或插画的风格，用 emoji / SVG 示意并说明成片会用什么方式实现）。
3. 用 `python3 <工具目录>/template/scripts/sheet.py --dir <样帧目录> --cols 2 --width 800 --out <样帧对比.jpg>` 拼成一张（或逐张展示），在回复里嵌图，然后再提问。样帧放在 `<输出目录>/<中文项目名>/样帧/`（此时还没建工程）。
4. 用户可以混搭（「A 的配色 + C 的角色」），记下来。

## 第二轮：定细节

| id | 问题 | 常见选项 |
|---|---|---|
| assets | 素材版权边界 | 宽松合规：自有素材 + AI 生图 + 可商用音乐，第三方 logo 仅指代（推荐）/ 严格：无第三方 logo、CC0 音乐 / 更宽松：风险用户承担 |
| showcase | 要重点展示的功能/作品 | 列出预调研找到的候选，多选；问是否有必须出现 / 必须排除的 |
| screens | 真实截图来源 | 公开页面 + 帖子/文档里的作品图（推荐先做全量盘点，告诉用户能拿到多少张）/ 需要登录才能看到的页面：请用户在 Chrome 窗口登录 / 用户直接提供截图或录屏 |
| music | 配乐 | 给 3~4 段 30 秒试听（`工程/out/配乐候选/`），请用户选；或问曲风偏好（电子 / 放克 / 励志史诗 / 轻快流行）/ 用户自带曲目 |
| cta | 网址与行动号召 | 网址写哪个、放在哪（至少放在最高潮一次 + 片尾）、按钮文案 |
| credit | 作者/品牌背书 | 重点讲 / 一笔带过 / 不出现 |
| web | 网页版 | 本地运行（推荐先这样）/ 部署到 EdgeOne Pages / Vercel / 嵌入现有站点 |
| review | 中途审阅 | 需求确认后全自动做完再交付（默认）/ 先出粗剪再精修 / 先出静帧分镜 |
| export | 导出规格 | 4K60 + 1080p60（推荐）/ 1080p60 / 4K30 |

最后一题固定为：

| confirm | 以上共识是否准确？确认后开始全自动制作。 | 准确，开始制作 / 有地方要调整 |
